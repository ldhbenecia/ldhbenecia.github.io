# 코드 주석

주석은 다음에 이 코드를 읽고 고칠 사람을 위한 것

## 무엇을 쓰나

**코드만 봐서는 알 수 없는 것만**

- 왜 이렇게 했는지 — 다른 방법을 쓰면 무엇이 깨지는지
- 지켜야 하는 조건 — 순서, 같이 바꿔야 하는 곳, 락 안에서만 불러야 하는 것
- 디자인 규칙 — 왜 이 값인지 (두 줄 제한, 접근성 대비, reduced-motion 처리 등)

## 쓰지 않는 것

- 코드를 한국어로 다시 읽어 주는 설명
- 개발 과정 이야기 (`기존에는 ~였다`, `예전에는 ~해서`, 조사 경위, 이전 구현 비교) — 커밋·PR·ADR 에
- 문서 경로·번호 (`docs/plans/...`, `ADR-12`, `P0-3`) — 문서는 옮겨지고 번호는 바뀜

## 형식

- 한두 줄, 명사형 종결(`~함`, `~됨`), 끝 마침표 X
- JSDoc(`/** */`) 쓰지 않음. `//` 로 통일 (CSS는 `/* */`)
- 필드·상수 설명은 그 줄 끝 `//` 로

```tsx
// ✅
const RACE_MS = 18_000  // 실제 크론이 걸리던 시간. 줄이면 비교의 의미가 사라짐

// ✅
// 두 겹의 제목이 같은 위치에 있어야 수면선에서 이어져 보임. 한쪽만 바꾸지 말 것
<h1 className={styles.above}>...</h1>

// ❌ 코드를 다시 읽어 줌
// 버튼을 누르면 타이머를 시작한다

// ❌ 개발 과정
// 기존에는 shadcn 카드였다

// ❌ 문서 번호
// ADR-3 참조
```
